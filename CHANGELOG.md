| 2026-10-09 | harbor-omp | Extracting the omp adapter from its eval harness: the Harbor half and the harness half were fused through a profile import and four harness modules, so neither half was reusable and neither was publishable in a public repo | Everything harness-shaped is data a caller can pass: seed content, run flags, a plugin checkout, extra files, pre/post commands. Two of those hooks must stay asymmetric on purpose — a pre-command is a pre-spend gate, a post-command must be structurally unable to change a verdict — because collapsing them into "best-effort commands" removes the gate that keeps a broken environment from being paid for | Put the whole contract on the option surface, document the hook semantics where they are implemented (`hooks.py`), and enforce the seam with both a runtime import check and a source scan, not with discipline | Built `harbor_omp` 0.1.0: `OmpOptions` carries every input, `hooks.py` documents the three extension points, plugin/config/session/install modules are split along their dependency boundaries, and 74 tests run without Docker, a network or a key | `src/harbor_omp/*`; `tests/`; VERIFY.md rows for each check |
| 2026-10-09 | harbor-omp | Five defects surfaced while porting, none of them visible from reading the old code: a trailing-slash pathspec false-positived the "missing at HEAD" check, two writers leaked the host's newline translation into the container, the version option was a silent no-op, and a non-numeric usage field aborted the whole metric read | The old adapter's tests asserted the *shape* of commands, which is why a pathspec that never matched and a `\r\n` that shipped could both pass for months. Only executing the adapter's own script and reading back uploaded bytes exposed them | For every ported helper, write the test against real bytes and real execution before trusting the port; treat "the old tests passed" as no evidence at all | Fixed all five; each has a row in `DEFECTS.md` with the command that reproduces it, and the red case is exercised in `VERIFY.md` where the check lives | `DEFECTS.md` rows 1–5; VERIFY.md ship/isolation/metric rows |
| 2026-10-09 | harbor-omp | Deliberate behaviour changes against the source adapter had to be chosen rather than inherited: provenance records renamed to generic names, the hooks moved into the agent's own shell, the config home now always reset, and `version()` now reports the measured CLI version instead of the pin | Every one of those follows from the same rule — the package may not know a benchmark, and may not claim a value it did not observe. The reset is the one real behaviour change: an always-empty-unless-seeded home makes "what the trial resolved" a property of the adapter rather than of the image | Keep the changes visible: document each in the README (options table, known gaps) and in `docs/architecture.md`, so a consumer comparing rows old-to-new can explain a difference instead of discovering it | Documented in README (options table, capabilities and known gaps), `docs/architecture.md` (lifecycle + seam), and `docs/other-harnesses.md` (what travels without Harbor) | README.md; docs/architecture.md; docs/other-harnesses.md |
| 2026-10-09 | harbor-omp | The ATIF converter — the largest gap in the adapter standard — did not fit this extraction's scope, and shipping a half-converter would be worse than shipping none | A seam is useful only when it is named in three places: the capability flag stays false so Harbor refuses rather than under-delivers; the reader the converter needs already exists and is tested; and the wiring point (`convert_trajectory`) is documented with the steps the follow-up takes | Land the adapter without ATIF, keep `capabilities.atif` false, and record the seam so the converter is a bounded change rather than a rediscovery | Recorded the seam in `docs/architecture.md` ("The ATIF seam (not implemented)") and in the README known-gaps table; `tests/test_package.py` fails if the capability is flipped without a converter | docs/architecture.md; README.md; tests/test_package.py |
