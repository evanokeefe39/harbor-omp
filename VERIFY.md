Lifecycle stages this ledger covers: author → install → eval run → PR + review → monitor. (A published-package stage is not yet covered: this repo has never been released.)

## Ledger

| scope | stage | check | command | proves | doesn't prove | goes red | concurrency safe | expected runtime |
|---|---|---|---|---|---|---|---|---|
| `src/harbor_omp/session.py` | author | a session directory sums to its tokens, cache, cost and steps, an unreadable line is counted rather than raised, and a directory with no JSONL is absent (`None`), never zero | `uv run pytest tests/test_session.py -q` | the trial's metric numbers are the session's numbers, and an absent session cannot be mistaken for a free one | that omp writes this JSONL shape in every version — the fixture is one measured shape | change the fixture's `cacheRead` from 1000 to 999: the cache total and the streamed-event assertions fail (exercised 2026-10-09) | yes | <5 s |
| `src/harbor_omp/omp_agent.py` | author | `populate_context_post_run` fills `AgentContext` from the fixture: input includes cache read + cache write, cache is reported separately, cost is omp's own, steps land in metadata | `uv run pytest tests/test_context.py -q` | the only metric source for a non-streaming run is correct, including the cache-inclusive input convention | that the numbers match a provider invoice | set `n_input_tokens = usage.input_tokens` (drop cache): 2 tests fail with `assert 150 == 3850` (exercised 2026-10-09) | yes | <5 s |
| `src/harbor_omp/options.py` + install | author | the `version` option is what the install installs — a scoped spec passes through, a bare `18.6.1` becomes the omp package at that version, and a blank value is refused before any container command | `uv run pytest tests/test_options.py -q` | the pin is a default, not a hard-code: what the caller asked for is what bun installs | that the registry serves that version | make `package_spec` return the pinned constant: 2 tests fail, and the install command shows `@18.6.0` where `@18.6.1` was asked (exercised 2026-10-09) | yes | <5 s |

| `src/harbor_omp/omp_agent.py` | install | the config home is reset before anything lands in it: the shipped config tar is extracted into `<config_home>/.omp` after the reset and before any hook command, and the seed is copied in after the reset | `uv run pytest tests/test_config_ship.py -q` | the isolated home is built by the adapter, so what a trial resolved is what the adapter put there | that omp reads only that directory | move the extract before the reset: the recorded order assertion fails and the extract command names a directory that is wiped afterwards | yes | ~20 s |
| `src/harbor_omp/omp_agent.py` | eval run | the run is observable before it happens: the exact argv is recorded before omp launches, the recorded instruction is the rendered one, and `install_only` records the argv and runs nothing | `uv run pytest tests/test_run.py -q` | a trial's identity exists even for a run that fails or never starts, and the zero-spend gate really spends nothing | that the agent obeys the argv | drop the `install_only` early return: the test sees an exec where it must see none | yes | <10 s |
| `src/harbor_omp/omp_agent.py` | install | the extension point's files are uploaded whole, and a named host file that is not readable aborts the setup | `uv run pytest tests/test_run.py -k extra_files -q` | a hook that silently received nothing cannot produce a silently degraded trial | that the container preserves file modes — it does not, by design | skip the upload loop: the recorded uploads are empty and the target lookup fails | yes | <5 s |

## Not covered here (named, not hidden)

- **A real Harbor trial** in a sandbox (Docker/Daytona): no test in this repo starts a container, so the install recipe against a real image and the mount of `/logs/agent` are unverified by this ledger. That is the next check to add, and it needs a configured environment.
- **ATIF correctness**: nothing to check until the converter exists (`capabilities.atif` is false).
- **Live streaming**: `remote_session_logs_dir` is asserted to be inside the mounted log dir, but Harbor's sync loop has never been run against it.
