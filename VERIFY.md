## Not covered here (named, not hidden)

- **A real Harbor trial** through Harbor's own machinery: the container-side recipes were exercised directly on Docker (the `scripts/container_smoke.py` row, run 2026-10-09 on ubuntu:24.04: bun 1.4.2, `omp/18.6.0`, the seed landing under the isolated home, and the hook semantics on GNU bash), and the documented invocation is resolved with `--print-config` (the `README.md` row), but nothing here has driven `harbor run` against a task — so Harbor's environment class, the `/logs/agent` mount and the upload path are unverified by this ledger. That is the next check to add, and it needs a configured environment.
- **ATIF correctness beyond the validator**: the trajectory is converted and validated from the fixture in the suite, and a real 1.1 MB session (217 lines → 217 steps, `TrajectoryValidator` clean) was converted by hand while writing this ledger — but no viewer, `atif2otel` export or observability plugin has been run against the artifact here, so what a consumer *displays* is unverified.
- **Harbor's live polling loop**: `convert_trajectory` is asserted against the streamed layout (`<logs_dir>/sessions`) and a `--stream` job's per-poll call is Harbor's loop, not this package's — nothing here has run `sync_trajectory`, which needs an environment with `stream: true`. What such a job produces is stated in the README's capabilities row.
